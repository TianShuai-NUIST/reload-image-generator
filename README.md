# reload-image-generator

一个用 C 写的图像生成器：**改配置文件，不重启进程就生效**。

热重载这件事看起来是"监听文件变化"，实际上难的是**变化到达的那一刻，读到的东西是否完整**——所以这里同时用了 `inotify`（及时性）和原子写入（一致性）。

## 它做什么

- 读一个脚本/配置文件，生成 P6 PPM 格式图像
- 配置文件一改，进程内的参数立刻跟着更新，不需要重启
- 数据结构按 config / ppm / utils 三层拆开，方便替换生成逻辑

## 怎么跑

```bash
make build          # 编译，产物在 build/reig
make run            # 用 scripts/in.fp 作为输入跑一遍
make test           # 解析器单测
make profile        # 带 -pg 编译，配合 gprof 看耗时
```

依赖：clang（或 gcc）、make。没有第三方库。

## 两个关键实现

**1. 用 inotify 替代轮询**

轮询的问题不是慢，是空转——CPU 一直在跑 `stat`，而且响应延迟等于扫描间隔。改成监听目录事件后，空闲时几乎不占 CPU，响应在毫秒级。代价是要自己处理事件合并（一次保存可能触发多个事件）。

**2. 信号 + 原子写入**

重载时最怕读到一个写了一半的文件。做法是写入端先写临时文件再 `rename` —— `rename` 在同一文件系统上是原子的，读端看到的永远是旧文件或新文件，不存在中间态。读端由信号触发重读，避免在信号处理函数里做重活。

## 已知限制

- 配置目录被删除或改名时没有降级处理，会直接失去监听
- 只支持单文件配置，没有 include 语法
- 输出格式只有 P6 PPM（下一步可能加 PNG）

## 为什么有这个项目

为了给后续写 DSL 做准备——一个能热重载的运行时，是解释器最实用的落地形态。
